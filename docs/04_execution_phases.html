NLP-06 Execution Phases

A dependency-ordered build plan for the privacy-preserving ward assistant — ten phases, each with a named owner and a falsifiable exit gate. Reconciles the PRD, Technical Execution Plan, Prototype Guide, and Research Guide into one sequence.

2-person team Person A · product Person B · research Mentor: Dr. M. S. Srividya

Read this first

Three assumptions that must be tested before the plan is committed

Each of these is load-bearing for a headline claim, and each is currently unverified across all four documents. Discovering any of them in Phase 4 costs weeks; discovering them in Phase 0 costs days.

Blocker risk · affects the core novelty claim

Synthea may not emit vitals at ward-telemetry cadence

Synthea generates observations tied to encounters, not continuous monitoring. A generated patient may have vitals recorded months or years apart. The plan assumes 12-timestep sliding windows with stride 1 read as short-horizon ward telemetry — if the real inter-observation gap is measured in months, those windows are longitudinal life-history, not monitoring data.

Why it matters: the gap claimed against b5 is that no clinical RAG study integrates real-time telemetry. If the primary dataset has no telemetry, that claim cannot be made on it. Resolve in P0: generate 50 patients, plot the distribution of inter-observation gaps per vital, and decide between synthesizing intra-encounter telemetry, reframing the temporal unit honestly, or escalating MIMIC-IV back to primary.

Design gap · undefined in every document

PTB-XL has no defined mapping onto the model input

PTB-XL is 10-second 12-lead ECG waveforms at 100/500 Hz. The models take a [batch, 12, 6] tensor of six tabular vitals. The Research Guide says to "process into the same window format so the same model code runs on it," but no mapping exists that is both mechanical and physiologically meaningful.

Options, best first: derive per-interval features (rate, variability, interval durations, ST level) into 12 × N windows — keeps the architecture, defensible; or accept a different input width for PTB-XL and claim only that the shape of the ε-trend transfers, not absolute F1. Naively downsampling raw leads into 12 × 12 is not defensible. Decide in P0, because P2 builds the pipeline.

Statistical defect · C2 cannot reach significance as specified

The stated test for C2 is underpowered by construction

The Research Guide specifies Mann-Whitney U on 5 seeds vs 5 seeds, at 6 ε levels × 2 comparisons, with Bonferroni correction. With n = 5 per group there are only C(10,5) = 252 arrangements, so the smallest attainable two-sided p is 2/252 ≈ 0.0079 — obtained only under perfect separation. The Bonferroni threshold for 12 tests is 0.05/12 ≈ 0.0042. The floor sits above the threshold: no possible experimental outcome can reach corrected significance.

Fix, best first: replace the 12 pairwise tests with one omnibus model over architecture × ε (aligned rank transform, or a mixed model on seed) — more powerful and the better-matched question anyway; report per-ε effect sizes with confidence intervals as description, not inference. If pairwise tests are kept, either raise to 6+ seeds or cut to 3 ε levels of interest. Decide in P0, because the seed count fixes the compute budget.

Sequencing

The critical path runs through the data freeze

Phase 4 is the long pole and it is serialized behind an immutable dataset. Every hour saved before the freeze is an hour the campaign starts earlier; every change made after it invalidates completed runs. The product track runs parallel and off the critical path — which means Person A has slack that should be spent on the campaign and figures, not on UI polish.

critical path parallel / feed-in hard freeze gate

The plan

Ten phases

Organized by dependency rather than by week, so the sequence survives schedule slip. A phase is done when its exit gate passes — not when its tasks feel finished.

P0

Feasibility spikes

A + B critical path

Kill or confirm the assumptions the rest of the plan rests on, before any of it is built. Time-box hard — the deliverable is four written answers, not four working systems.

  • S1 · Telemetry cadence. Generate a small Synthea cohort; measure the inter-observation gap distribution per vital. Decide the temporal unit the paper will claim.
  • S2 · Opacus × Flower × sequence models. Get one ward node training two federated rounds with DP and a reported ε. Note that nn.LSTM is not supported by Opacus's grad-sampler — DPLSTM/DPGRU are the substitutes, and the accountant must carry state across rounds for a 100-round ε to mean anything.
  • S3 · PTB-XL mapping. Choose and document how real ECG becomes model input.
  • S4 · Compute budget. Wall-clock one full run on the actual hardware, multiply by the grid, and size the grid to fit the time available. DP-SGD computes per-sample gradients and is far slower than standard training.
Exit gate
  • All four spikes answered in writing, with the decision recorded — no open "we'll figure it out later."
  • Final experimental grid size fixed (models × ε levels × seeds) and shown to fit the measured compute budget.
  • Statistical plan for C2 revised and agreed.
P1

Scope lock & foundation

A + B critical path

Collapse four documents that currently disagree into one source of truth, and stand up the environment both members will work in.

  • Publish the reconciliation decisions (table below) as the single authoritative scope. Retire contradicting sections of the PRD rather than leaving both versions live.
  • Repository skeleton per the Prototype Guide layout; branch-per-track; pinned requirements.txt.
  • Ollama installed, model pulled, latency benchmarked on the demo machine.
  • Annotate b1–b5 and draft the related-work outline and gap table.
  • Decide whether to submit MIMIC credentialing at all — with Synthea as primary it is now optional insurance, not a dependency.
Exit gate
  • Both members and the mentor have signed off on one scope document; no feature is "maybe."
  • A clean checkout installs and runs a local LLM prompt end-to-end on both machines.

depends on: P0

P2

Data pipeline → hard freeze

A + B critical path

Produce every dataset variant the project will ever use, then freeze them. This is the single most consequential gate in the plan: a labeling change after the campaign starts invalidates every completed run.

  • PhysioNet/CinC 2019 extraction; forward-fill imputation with the per-vital rate recorded, since that rate has to appear in the paper.
  • Labels come with the dataset — hourly sepsis onset. No labelling scheme needs deriving; NEWS2 is optional as a secondary comparison only.
  • Sliding windows; client partitioning by hospital system; report the realised class balance (~1.5% positive) and per-site differences, because both interact with DP noise.
  • Subsample the ~800,000 available windows to fit the compute budget, and record the sampling rule.
  • Encrypted volume (LUKS or encrypted Docker volume) with ChromaDB and SQLite both living inside it — this is what removes the encryption limitation from the paper.
  • Embed patient records into per-patient ChromaDB collections with strict patient_id metadata.
Exit gate — freeze conditions
  • Every dataset variant is versioned and content-hashed; the hash is recorded and every downstream experiment logs it.
  • NEWS2/MEWS agreement computed and recorded.
  • A cross-patient retrieval probe returns nothing — the privacy boundary fails closed, verified by test, not by inspection.
  • The raw database file is confirmed unreadable outside the encrypted volume.
  • No phase past this point may begin until the hash exists.

depends on: P1

P3B

Federated + DP training harness

Person B critical path

Build the machinery the campaign will run unattended. Build it in the order below — each layer is only debuggable once the one beneath it is known good.

  • Centralized single-node baseline first, to establish the no-FL, no-DP performance ceiling.
  • Flower FedAvg across five ward clients, still without DP — confirm convergence.
  • Opacus DP-SGD per client, with the Rényi accountant persisted across rounds; verify the achieved ε lands within tolerance of the target.
  • Dockerize ward nodes over gRPC — this is what converts "simulated federation" into genuine process-level federation in the paper.
  • Dropout strategy for the client-unavailability experiment.
  • Experiment runner: config-driven, checkpointed, resumable, writing one complete result row per run (F1, precision, recall, AUC-ROC, false negative rate, achieved ε, wall-clock, dataset hash, seed).
Exit gate
  • One full (model × ε × seed) run completes unattended and writes a complete result row.
  • Killing the runner mid-campaign and restarting resumes without duplicating or losing cells.
  • Achieved ε matches target ε within an agreed tolerance.

depends on: P2 freeze

P3A

Product track build

Person A

The patient-facing assistant and the doctor dashboard shell. Runs fully parallel to P3B — it needs the frozen data but nothing from the research track.

  • RAG layer: embedder, retriever with the where patient filter as the enforced privacy boundary, prompt builder with an explicit refusal instruction when context is insufficient.
  • Ollama client at low temperature; FastAPI endpoints for query, ingest, alerts, and scoring.
  • Streamlit patient chat and doctor dashboard shell (alert list wired to a stub until P5).
  • Lab-report PDF ingestion into the patient's collection.
  • Generate the synthetic encounter notes that populate the RAG knowledge base.
Exit gate
  • A patient question returns an answer traceable to that patient's own record.
  • An adversarial probe for another patient's data returns nothing — tested, not assumed.
  • No outbound network call occurs during inference.

depends on: P2 freeze

P4

Experimental campaign

B leads · A supports critical path · long pole

Execute the full grid unattended. This phase is mostly waiting, which is exactly why the paper's Methods and Related Work sections should be written during it.

  • Core grid on PhysioNet: ε levels × architectures × seeds. Set the seed count from the revised statistical plan, not from convention.
  • Client-dropout and latency robustness run.
  • Non-IID skew intensity sweep if compute remains.
  • Opportunistic result, nearly free: the five wards are already non-IID, so per-ward metric breakdowns at each ε will show whether DP noise degrades some wards more than others. Disparate impact of DP across subgroups is an established effect and reporting it per-ward costs nothing beyond a groupby.
Exit gate
  • Every grid cell has a result row — no silently failed or missing cells.
  • Every row carries the frozen dataset hash and its seed.
  • Spot-rerunning one cell reproduces its recorded metrics.

depends on: P3B

P5

C3 bridge integration

A leads · B supports

Wire an anomaly alert to a patient-scoped RAG summary — the architectural connection that is C3's actual novelty. Start this against the first trained checkpoint from P3B; it must not wait for the campaign to finish.

  • Risk scorer serving the trained model; alert bridge that identifies which vitals are abnormal and builds the alert-specific retrieval query.
  • Alert-summary prompt with explicit no-treatment-recommendation and no-fabrication constraints.
  • Live alerts in the doctor dashboard, ranked by risk, with drill-down and follow-up query.
  • Full end-to-end flow: reading arrives → scored → alert raised → summary generated → clinician reviews → follow-up answered.
  • Run the privacy audit checklist against the assembled system.
Exit gate
  • The end-to-end walkthrough runs start to finish without manual intervention.
  • Privacy audit passes: no egress, per-patient isolation holds, storage encrypted, no patient data in logs or session state.

depends on: P3A + first checkpoint from P3B

P6

C3 evaluation

A + B

Three independent evaluation layers over the same alert summaries. The programmatic layer is the strongest of the three and the cheapest to defend, because ground truth is fully controlled.

  • Generate 20–30 alert scenarios from held-out patients — hold them out at the P2 freeze, not later.
  • Human rubric: two raters scoring independently, then Cohen's κ.
  • LLM-as-judge across multiple judge models on the same rubric.
  • Programmatic fact-verification: extract claims, check each against the source record, report an objective hallucination rate.
Exit gate
  • All three layers reported with numbers, including κ and the objective hallucination rate.
  • Disagreements between human, LLM-judge, and programmatic layers are explained rather than averaged away.

depends on: P5

P7

Analysis & figures

B leads critical path

Turn result rows into the paper's claims. Every number that appears in the paper originates here and nowhere else.

  • Run the revised statistical plan from P0. Identify ε* — the budget below which utility falls under the pre-declared clinical threshold — and justify that threshold in the paper rather than picking it after seeing results.
  • Interpret false negative rate as the clinically dominant metric; a missed deterioration is not symmetric with a false alarm.
  • Generate all figures from scripts reading the results files — never hand-assembled, so a rerun regenerates the paper.
  • Build the results tables as mean ± std across seeds, with the achieved ε alongside the target.
Exit gate
  • Every figure and table regenerates from a single command against the frozen results.
  • No number in the draft exists outside a generated artifact.

depends on: P4 (+ P6 for the C3 section)

P8

Paper

B leads · A supports critical path

Deliberately overlapped with P4–P7. Methods, Related Work, and the System Architecture section describe decisions already made and should be written while the campaign runs.

  • During P4: Introduction, Related Work with the gap table, System Architecture, Data and Preprocessing, FL+DP Methodology.
  • After P7: Results, Discussion, Conclusion.
  • Limitations written to the fixed / mitigated / defended structure — state plainly what remains genuinely limited rather than defending everything.
  • Secure all citations, including the labeling protocols, the DP and FL foundations, and the real-signal dataset.
  • Mentor review, then revision.
Exit gate
  • Complete draft reviewed by both authors and the mentor, with feedback incorporated.
  • Every claim in the abstract traces to a specific figure or table.

depends on: P7 (overlaps P4–P7)

P9

Hardening & defense

A + B critical path

Make the demo reliable and the work reproducible by someone else.

  • Rehearse the full demo end to end at least twice; record a fallback video against live-demo failure.
  • Public repository with a README that reproduces the pipeline from scratch, plus supplementary tables and configuration.
  • Slides or poster; prepare answers to the predictable challenges — why synthetic data, why this ε range, why these labels, what "federated" means here.
  • Ethics, author-contribution, and conflict-of-interest statements.
Exit gate
  • Demo runs twice consecutively without failure.
  • A clean clone of the repository reproduces at least one paper figure unaided.

depends on: P8

Agree this before you need it

De-scoping ladder

A plan without a pre-agreed cut order gets cut under pressure by whoever panics first, and the thing that gets dropped is usually the thing that mattered. Descend this ladder in order; the bottom rung is non-negotiable.

  1. Drop GRU, keep LSTM vs CNN.C2's hypothesis is about recurrent vs convolutional. One recurrent architecture tests it. Cuts the core grid by a third.
  2. Drop PTB-XL validation.Its purpose was to prove the finding was not an artefact of synthetic data. The primary dataset is now real, so that objection no longer exists. Reclaims ~5.5 days — spend it on seeds.
  3. Drop the client-dropout robustness run.Nice defensive result; not load-bearing for any contribution. Restate as future work.
  4. Drop the voice pipeline.Restored as a demo feature, but explicitly not a contribution — so it is the first product-track item to go if the schedule tightens.
  5. Drop lab-report PDF ingestion.Demo polish. The RAG pipeline is already demonstrated by the notes corpus.
  6. Drop the MEWS cross-check, keep NEWS2.Weakens the labeling defense from "two validated schemes agree" to "one validated scheme" — a real but survivable loss.
  7. Never cut: the seed count, or the C3 bridge.Seeds are a validity constraint, not a scope choice — below the count the statistical plan requires, every comparison claim becomes indefensible. The C3 bridge is the only contribution with no analogue in b1–b5; without it the paper is an ε-sweep with a chatbot attached.
